# Android AAR boundary

CI compiles, runs JVM unit tests, and lints this library with Java 17, Gradle 8.10.2, Android 35, CMake 3.22.1, and NDK 27.2.12479018. The module pins the NDK version so JNI diagnostics stay reproducible.

The Android library now contains:

- a versioned, opaque-handle C ABI (`arkernel/c_api.h`);
- JNI ownership and data marshalling without nanosecond-to-Double conversion;
- `ArKernelVio`, a synchronized Kotlin `AutoCloseable` facade;
- `AndroidImuSource`, a dedicated-thread SensorManager adapter;
- pause/resume/reset behavior that never mixes sensor sessions;
- NDK/CMake wiring for `libarkernel_jni.so`.

## Reconstruction quality planner

`ArKernelReconstructionPlanner` exposes the portable C++ environment/object capture planner through JNI. It combines timestamp-matched world pose, tracking/features, pre-copy sharpness/clipping, pose uncertainty and optional object ROI into an accepted/rejected decision with a stable reason, score, view bin and coverage. The decision can drive `ArKernelSession.reconstructionQualityGate` before I420 copying. Camera pipelines use tokenized `reserve()` and publish keyframe/coverage state only through `commit()` after durable storage; `cancel()` rolls back copy, queue or storage failures.

`ReconstructionScanController` is the recommended integration owner: pass its `qualityGate` and `reconstructionFrame` methods to `ArKernelSession`. It reserves before colour copying, submits to the bounded writer, commits only after `AtomicFile` succeeds, and cancels every conversion, backpressure, storage or lifecycle failure. `ReconstructionFrameArchive.newScanController(...)` constructs the full chain.

## Reconstruction frame archive

`ReconstructionFrameArchive` stores selected full-resolution frames as independent atomic, bounded `ARKFRM01` envelopes in app-private no-backup storage. Exposure, ISO, calibrated pose and uncertainty remain attached to the pixels, while `arkf://` references cross the portable capture boundary. Camera2 metadata is matched by exact sensor timestamp, arbitrary YUV plane strides are copied to canonical I420 before `Image.close()`, and `BoundedReconstructionFrameWriter` moves storage off the camera callback with explicit backpressure. After accepted global optimization, `publishOptimizedPoses` atomically installs a monotonic `ARKPOS01` pose manifest without rewriting image payloads; `loadWithOptimizedPose` resolves exact frame-ID/timestamp matches. Deletion or eviction invalidates the whole manifest to prevent mixed pose generations. CRC detects accidental corruption but is not encryption; host apps must provide retention/deletion policy for sensitive imagery.

## ARCore-independent runtime

`StandaloneArRuntime` is the guaranteed fallback and directly owns the existing Camera2 + SensorManager + native VIO/mapping session. `StandaloneArSupportProbe` verifies accelerometer, gyroscope, back-camera YUV size, and the configured camera ID before startup. `ArRuntimeSelector` may try an application-supplied `OptionalExternalArRuntimeFactory` (for example a separately packaged ARCore adapter), but falls back on absence, unsupported status, or creation failure without linking this AAR to ARCore. Intrinsics and camera-to-IMU extrinsics remain mandatory device calibration inputs; package presence is never treated as proof of ARCore support. See `docs/FALLBACK.md`.

Host apps own CAMERA runtime permission and lifecycle calls. Typical use:

```kotlin
val vio = ArKernelVio()
val imu = AndroidImuSource(context, vio)

override fun onResume() { super.onResume(); imu.start() }
override fun onPause() { imu.stop(); super.onPause() }
override fun onDestroy() { imu.close(); vio.close(); super.onDestroy() }
```

## Calibrated Camera2 stream

`StandaloneArSupportProbe.inspectCompatibility` builds a privacy-safe versioned capability signature from the exact YUV stream, camera metadata, physical-camera set, IMU properties, ABI, memory class, and hashed build fingerprint. It returns stable reason codes and never grants metric admission from static declarations alone. A host can attach `ActiveDeviceCompatibilityProbe` when creating the standalone runtime; bounded camera image/result and raw IMU timing hooks then measure monotonicity, rates, jitter, gaps, exact timestamp pairing, stream overlap, and observed realtime-versus-uptime behavior. `ActiveCompatibilityTestController` can terminally finish that probe after a fixed bounded window so mapping cannot remain pending accidentally. Mapping remains explicitly paused until the terminal active report passes with trusted camera and camera/IMU calibration. An optional bounded `GuidedRotationObservabilityProbe` compares signed visual rotation with the exact camera-axis IMU prediction supplied to each frame, requiring observable motion and rejecting direction or magnitude disagreement without silently rewriting extrinsics. `GuidedTimeOffsetObservabilityProbe` correlates changing multi-axis visual and body-to-camera gyro angular rates over a bounded ±100 ms grid; weak, ambiguous, boundary, single-axis or constant-motion results are rejected, and accepted results carry conservative peak-width uncertainty/variance. `GuidedTimeOffsetDriftProbe` robustly combines up to 32 accepted windows over at least 60 seconds, reporting ppm drift, uncertainty and residual while rejecting noisy or excessive fits. Neither modifies the live clock mapping. `AdmissionEvidenceStore` can atomically retain the active and guided results in no-backup app storage, but only under an exact capability-signature, calibration-hash, software-revision and expiry match; this advisory cache never bypasses continuous monitors and is not dimensional-validation evidence. `AndroidImuSource` no longer pairs an event with an arbitrarily old value from the other sensor: `ImuSampleSynchronizer` emits strictly increasing common timestamps using bounded interpolation between real samples and never extrapolates. `CameraTimestampNormalizer` withholds initial frames until bounded observations distinguish realtime, uptime, or practically equivalent clocks; one locked median uptime offset then places both Image and CaptureResult timestamps in the IMU realtime domain. Later images continuously check that uptime offset, realtime callback residual, or equivalent-clock relationship has not jumped. A violation terminally stops normalized frames, reports `CAMERA_CLOCK_DISCONTINUITY`, and pauses all mapping until a new session is admitted. In parallel, a subsampled bounded JNI `ArKernelClockAligner` robustly fits affine camera-to-callback time over a minimum ten-second span; `CameraClockDriftPolicy` rejects excessive scale drift in ppm or callback residual RMSE without using that noisy callback fit to rewrite timestamps. `Camera2FrameSource` opens a back camera (or an explicit camera ID), requests the exact calibrated YUV size, consumes only the Y plane, and closes each `Image` after the synchronous native call. The host must pass intrinsics/distortion for that exact camera ID, output size, crop and stabilization mode; the adapter intentionally refuses to guess calibration. The requested size must be listed by that camera's `StreamConfigurationMap`.

## Coordinated session

`ArKernelSession` queues IMU samples and drains only samples with `timestamp <= Image.timestamp` before each visual frame. It then computes an IMU rotation prediction, runs the visual frontend, and feeds valid general-3D relative poses back into VIO. A calibrated `bodyFromCameraRotation` is mandatory because Android device axes and optical camera axes are generally not aligned; `bodyFromCameraTranslationMeters` carries the metric camera lever arm from the IMU/body origin. Result callbacks run on the camera worker thread.

A frame enters the sparse map at most once and only after `MappingQualityGate` accepts it. Uninitialized or limited VIO, non-tracking frontend state, fewer than 12 accepted tracks, or a new IMU queue overflow pause mapping immediately; three consecutive good frames are required before recovery. `ArKernelSessionResult.mappingGate` exposes `PAUSED`, `RECOVERING` or `ACTIVE` plus the precise reason. `ArKernelSessionResult.spatialMap` reports landmark changes and the bounded dominant plane for compatibility. `ArKernelSession.planes()` exposes all currently extracted surfaces with stable IDs, geometry statistics, observed area and gravity-aware `FLOOR`, `CEILING`, `WALL`, `SLOPED` or `UNKNOWN` semantics. Floor versus ceiling uses the current metric camera side of the plane rather than an arbitrary normal sign. `ArKernelSession.roomLayout()` reports selected floor/ceiling IDs and elevations, a plausibility-gated room height, and sums of observed—not extrapolated—floor, ceiling and wall areas. It does not claim that a partial scan is a closed room boundary. `raycastPlane` tests every active boundary and returns only the nearest valid hit inside observed plane geometry. `createAnchor`, `anchor`, and `removeAnchor` expose stable world-frame anchors. Stopping the Camera2 session resets this transient map and its anchors. `ArKernelSession.saveSpatialMap` exports the native snapshot into `ArKernelMapStore`, which uses Keystore AES-256-GCM, a fresh nonce, authenticated metadata, `AtomicFile`, and no-backup app storage.

Cross-session restore can use `restoreSpatialMapRelocalized` with caller-supplied trusted metric 3D correspondences, or `restoreSpatialMapMatched` after the running scene has accumulated confirmed overlapping landmarks. Repeated descriptors of each confirmed landmark are fused with a bounded bitwise majority vote before persistence and matching. The matched path applies Hamming, ratio and mutual-best gates; native deterministic RANSAC, non-collinearity, inlier-ratio and RMSE gates then decide whether landmarks and complete anchor poses may be transformed and installed. A failed descriptor or geometric gate leaves the active map unchanged. `restoreSpatialMapInCurrentWorld` remains an explicit expert path for an already aligned frame; large-scale place recognition remains outside this foundation. Encryption authenticates bytes but cannot establish spatial alignment. The full calibrated camera-to-body transform is used: mapping composes the rotated metric lever arm into `world_from_camera`, and visual scale correction compares predicted camera-center motion before converting the corrected camera position back to the body origin.

## Depth surfels

`integrateMetricDepthImage` accepts an aligned optical-axis Z-depth `FloatArray` in metres plus an optional confidence plane, performs distortion-aware native unprojection, configurable pixel-stride sampling, radius estimation, and discontinuity-gated local normals without constructing per-pixel Kotlin objects. Sustained pipelines can use `integrateMetricDepthBuffer` with direct native-order `FloatBuffer` inputs: JNI validates current element offsets, remaining capacity, alignment, strides, and optional confidence, then reads synchronously without copying the complete arrays. The host must not mutate or release either buffer until the call returns. `integrateSurfelObservations` accepts an already sampled bounded batch of positive-depth metric camera-space points, confidence, radius, and optional normals together with the exact frame-associated `worldFromCamera`. Stereo, monocular metric-depth, ToF, structured-light, or imported point-cloud adapters can use the same API; LiDAR is not required. The native core transforms samples into world space and confidence-fuses them in 5 cm voxels. Two observations are required before publication through `surfels()`. `raycastSurfel` returns the nearest bounded hit against normal-backed finite discs or approximate half-voxel-capped spheres when no normal is available; a miss is not evidence of observed free space. `renderSurfelDepth` produces a metric camera Z-buffer by distortion-aware per-pixel intersection with confirmed finite discs. `renderSurfelDepthInto` writes the same output synchronously into a reusable writable direct native-order `FloatBuffer` from its current position, avoiding a full JNI result allocation/copy; capacity must cover calibrated width times height and the position is not advanced. Zero remains unknown, normal-less surfels are omitted to avoid false occlusion, and `truncated` reports radius or work-budget clipping. Session writes return `null` unless the mapping gate is active. Relative depth or raw sensor units must be converted and calibrated by the adapter first. Surfels are transient and are not yet a TSDF, mesh, persisted map, or occlusion renderer.

## Temporal metric depth

`TemporalMetricDepthFilter` can conservatively stabilize a camera-aligned `MetricDepthBuffer` before session integration. `TemporalDepthInferenceBackend` can instead own/decorate a metric-depth or combined inference backend so filtering always occurs before the scheduler callback and normal session integration. It reprojects history with the exact previous/current world poses and calibrated distortion, z-buffers the predicted surface, and blends only current valid pixels that pass absolute and relative consistency gates. It never fills current holes. Frame order, gap, calibration, direct-buffer, and 4,194,304-pixel limits are explicit; telemetry reports blended and rejected history pixels.

## On-device inference SPI

`OnDeviceInferenceBackend` is the dependency-free Android boundary for separately packaged LiteRT, ONNX Runtime, MediaPipe, or host engines. Every backend exposes a validated `ModelManifest` with model/version ID, SHA-256, SPDX license, HTTPS source, tasks, input normalization/quantization (including quantized scale/zero point), labels, metric-depth conversion, byte size, and measured device profiles. `ArKernelTensorPreprocessor` can deterministically resize/normalize a direct camera frame into a reusable direct FLOAT32, INT8, or UINT8 NHWC tensor without adding an ML dependency. `ArKernelDepthPostprocessor` converts a direct one-channel model tensor into camera-sized metric depth plus interpolation-validity confidence, with explicit direct/inverse and unit conversion contracts. `MetricDepthTensorBackend.createVerified` composes both stages around a narrow `SingleInputTensorRuntime`, verifies the exact model bytes, reuses bounded raw tensor buffers, rejects partial runtime output, and leaves LiteRT/ONNX/delegate policy in a separately packaged adapter. `SemanticDetectionTensorBackend.createVerified` adds bounded row-based box decoding, clipping, confidence filtering and deterministic NMS while validating every class against the manifest. `AnchorFreeDetectionTensorBackend` supports bounded YOLOX-style objectness/class rows and RT-DETR-style normalized rows with probability, sigmoid, or softmax scores; `SsdDetectionTensorBackend` supports the four-output SSD/EfficientDet `Detection_PostProcess` contract. `DistributionFocalDetectionTensorBackend` decodes validated merged multi-level DFL rows used by NanoDet-/PicoDet-style exports; `SeparatedDistributionFocalDetectionTensorBackend` accepts an explicitly ordered class/regression tensor pair for every feature level. All remain runtime-neutral and reject malformed shapes, quantization, byte counts, classes, and candidate counts. A genuine multi-head model can use `DepthAndDetectionTensorBackend.createVerified` and `MultiOutputTensorRuntime` to preprocess and execute once, then emit co-timestamped metric depth and semantic boxes from explicitly ordered outputs. Classes configured as dynamic zero depth/confidence inside a padded, pixel-budgeted union of their boxes before temporal filtering or surfel integration. Adapters with one-channel class-index segmentation can use `ArKernelClassMaskPostprocessor` for bounded pixel-level FLOAT32/INT8/UINT8 masking instead of coarse boxes. `BoundedInferenceScheduler` runs one request at a time with no queue and explicit `RATE_LIMITED`, `THERMAL_PAUSED`, `BUSY`, `OUT_OF_ORDER`, and `CLOSED` results. An optional `InferenceCadenceController` uses bounded latency EWMA/p95 telemetry, target duty cycle, failure backoff, and host-supplied thermal state to adapt cadence without creating a queue. `AndroidInferenceThermalMonitor` can feed it from `PowerManager` on API 29+ while safely falling back to `NORMAL` on API 26–28. `PerceptionFrame` keeps direct image memory, calibration, timestamp, and exact world pose together; output cannot replace that pose. `TrackedInferenceBackend` can add bounded deterministic class-aware IoU IDs only to detections lacking model-provided IDs. `ArKernelPerceptionPipeline.create` owns the correctly ordered tracker → temporal-depth → adaptive scheduler → optional Android-thermal chain and offers direct submit-plus-session-integration without adding a queue. `integrateInferenceOutput` routes only declared metric depth and bounded semantic detections through existing session safety gates. No model or ML runtime is silently bundled. See `docs/INFERENCE.md`.

## Semantic 3D observations

`projectSemanticDetection` accepts a calibrated detection pixel plus the exact frame-associated `worldFromCamera` returned in `ArKernelSessionResult`; it unprojects a ray and can require an observed floor or wall boundary. No hit means no object. `integrateSemanticObservation` accepts a model-manifest class ID, optional source track ID, confidence, dynamic flag and an already metric world position. The host must derive that position from trusted depth, triangulation or bounded raycasting; a 2D detection alone is insufficient. The session returns `null` while its geometric mapping gate is paused. `semanticObjects()` exposes only confirmed objects, while `pruneSemanticObjects()` advances static/dynamic expiry even when an inference frame has no detections. Labels remain adapter-owned and class `0` means unknown. Semantic objects are transient and are not yet written to `ARKMAP01`.
