# Android AAR boundary

CI compiles, runs JVM unit tests, and lints this library with Java 17, Gradle 8.10.2, Android 35, CMake 3.22.1, and NDK 27.2.12479018. The module pins the NDK version so JNI diagnostics stay reproducible.

The Android library now contains:

- a versioned, opaque-handle C ABI (`arkernel/c_api.h`);
- JNI ownership and data marshalling without nanosecond-to-Double conversion;
- `ArKernelVio`, a synchronized Kotlin `AutoCloseable` facade;
- `AndroidImuSource`, a dedicated-thread SensorManager adapter;
- pause/resume/reset behavior that never mixes sensor sessions;
- NDK/CMake wiring for `libarkernel_jni.so`.

## Reconstruction quality planner

`ReconstructionFusionPipeline` is the lifecycle-safe Android owner for bounded sparse TSDF fusion and deterministic mesh production. It consumes direct native-order metric depth, confidence and optional uncertainty buffers with exact calibration/pose, rejects non-monotonic frames, and preserves sticky truncation evidence. It returns separate bounded GLBs for the filtered source mesh and conservative simplified mesh; an optional measured quadric-error-guided clustering LOD can further refine only the delivery mesh under explicit geometric, displacement and evaluation budgets. `buildSourceMesh()` additionally exposes only a fully completed filtered metric source as native-order buffers for texturing without reparsing a GLB. It is inference-runtime- and ARCore-independent and does not fill unknown space or claim watertightness.

`ArKernelDimensionalValidator` exposes the portable held-out scale-bar/survey/ground-truth evaluator through additive versioned C structs and JNI. It accepts at most 64 uniquely identified independent reconstructed point pairs, returns stable rejection reasons plus absolute/relative-error metrics, and cannot upgrade missing evidence into a centimetre claim. `ArKernelSurveyMeasurementCsv` is a bounded canonical CSV transport adapter for those observations with strict budgets, unique IDs, exact provenance, finite values and fail-closed parsing; it neither collects evidence nor grants a quality grade. `ArKernelReconstructionPlanner` exposes the portable C++ environment/object capture planner through JNI. It combines timestamp-matched world pose, tracking/features, pre-copy sharpness/clipping, pose uncertainty and optional object ROI into an accepted/rejected decision with a stable reason, score, view bin and coverage. The decision can drive `ArKernelSession.reconstructionQualityGate` before I420 copying. Camera pipelines use tokenized `reserve()` and publish keyframe/coverage state only through `commit()` after durable storage; `cancel()` rolls back copy, queue or storage failures. `ArKernelObjectCaptureGuidance` separately exposes the bounded isolated-object capture state machine through JNI: host-measured foreground/centre/pose observations produce exact phase, instruction, rejection, measured view coverage and a deterministic turntable target. It is UI-neutral, fail-closed on invalid/non-monotonic/unreliable observations and strict budgets, and does not segment images, actuate hardware or claim reconstruction quality. `ArKernelObjectCaptureGuidancePrompts` turns that exact result into bounded German/English host prompts with measured coverage detail and tone; it renders no UI. `ArKernelTurntableActuationController` adds a bounded host-owned actuation contract: only actionable orbit results become one-at-a-time commands with exact IDs, monotonic deadlines, step/target integrity and measured executed-step feedback; adapter faults and invalid feedback become terminal until reset. The host implements `ArKernelTurntableActuator`, and physical rig/device evidence remains open.

`ReconstructionFrameArchive` can optionally wrap retained colour frames and frame-owned depth companions in authenticated AES-256-GCM envelopes. The `ARKFEAD1` codec binds session ID, file name and colour/depth role through AAD, uses a non-exportable Android Keystore key and fails closed on tampering, swapped files, missing keys or invalid envelope bounds. `authenticatedEncryption`, `clear(deleteKey = true)`, `deleteEncryptionKey()` and `ReconstructionFrameRetentionController` are explicit host controls; the archive never deletes frames or keys automatically. Default plaintext `ARKFRM01`/CRC storage remains unchanged and the separate `ARKSES01` state archive stays CRC-only. `ArKernelRetentionStrings` supplies resource-qualified German/English retention dialog strings and a bounded UI-neutral selection/action contract: it rejects key deletion without authenticated encryption or with `KEEP`, marks destructive modes and requires explicit confirmation. `ArKernelRetentionDialog` renders those strings in a bounded platform dialog with three modes, dynamic key-deletion availability and explicit confirm/cancel; invalid choices stay open and report an error. It requires an Activity context with a window token, never deletes data automatically and leaves full app UX composition to the host. Physical-device lifecycle validation remains open.

`ReconstructionScanController` is the recommended integration owner: pass its `qualityGate` and `reconstructionFrame` methods to `ArKernelSession`. It reserves before colour copying, submits to the bounded writer, commits only after `AtomicFile` succeeds, and cancels every conversion, backpressure, storage or lifecycle failure. `ReconstructionFrameArchive.newScanController(...)` constructs the full chain.

## Reconstruction frame archive

`ReconstructionFrameArchive` stores selected full-resolution frames as independent atomic, bounded `ARKFRM01` envelopes in app-private no-backup storage. Exposure, ISO, calibrated pose and uncertainty remain attached to the pixels, while `arkf://` references cross the portable capture boundary. Camera2 metadata is matched by exact sensor timestamp, arbitrary YUV plane strides are copied to canonical I420 before `Image.close()`, and `BoundedReconstructionFrameWriter` moves storage off the camera callback with explicit backpressure. After accepted global optimization, `publishOptimizedPoses` atomically installs a monotonic `ARKPOS01` pose manifest without rewriting image payloads; `loadWithOptimizedPose` resolves exact frame-ID/timestamp matches. Deletion or eviction invalidates the whole manifest to prevent mixed pose generations. CRC detects accidental corruption but is not encryption; host apps must provide retention/deletion policy for sensitive imagery.

## Final reconstruction assets

`ReconstructionFrameArchive` may store CRC-framed optical-Z depth/confidence/uncertainty companions beside colour frames without introducing a second public reference; deletion and budget eviction remove both. `ReconstructionTextureSourceLoader` resolves the core's unique ascending frame/view table from opaque `arkf://` references as one bounded transaction, verifies exact frame/dimension/timestamp provenance and returns owned canonical colour bytes plus direct canonical depth buffers without per-triangle reference duplication. Its `ReconstructionTextureSourceDecoder` validates archived JPEG/PNG MIME type and dimensions against frame metadata, bounds decoded allocation and emits tightly packed top-left RGBA8; Gray8 and canonical I420 need no codec adapter. `ReconstructionTexturePipeline` passes those canonical sources, calibrated cameras, poses and bounded fused-mesh buffers through the complete portable graph over JNI; only a complete result exposes direct mesh buffers and RGBA pixels suitable for `ReconstructionTexturedAssetPublisher`. Optional aligned optical-axis depth, confidence and uncertainty use timestamp-bound direct buffers with Java and native range validation. Mandatory-depth mode rejects missing depth, and unknown/non-finite samples remain unknown rather than free space. `ReconstructionTexturePngEncoder` converts the portable core's RGBA8 atlas into a bounded lossless Android PNG while preserving alpha. Given a core-generated seam-aware mesh and baked atlas, `ReconstructionTexturedAssetPublisher` validates direct native-order mesh buffers, invokes canonical embedded GLB export through JNI and atomically publishes only the completed one-file result through `ReconstructionAssetArchive` under an opaque `arkglb://` reference. It validates exact GLB 2.0 JSON/BIN framing on every write and read, enforces per-file/count/total-byte budgets, and evicts the oldest generation deterministically. Publication atomicity and framing are not encryption or authenticity; hosts still own sharing and retention policy.

`ReconstructionTextureSourceLoader` now also returns each source's exact archived frame metadata, including an accepted optimized pose and its manifest generation, alongside its canonical pixels and frame-owned depth companion. `ReconstructionTexturedSessionPipeline` uses that single bounded resolution as one fail-closed transaction: it verifies unique ascending frame IDs, opaque references, strict timestamps, calibration dimensions, uncertainty and depth provenance; fuses those same observations; accepts only a complete direct fused source mesh; runs the full texture graph; and atomically publishes only after PNG encoding and embedded-GLB export succeed. The result retains exact per-frame provenance, fusion/mesh/texture telemetry and the failing stage/error, but exposes a final `arkglb://` reference only on completion. It does not assign texture metadata early, invent UVs or claim an assessed accuracy grade: the convenience GLB remains explicitly `unverified` until separate held-out physical evidence is evaluated. `ReconstructionSessionStateArchive` can persist terminal results as bounded versioned CRC envelopes under opaque `arkses://` references, with strictly increasing generations per session and deterministic session/generation/byte-budget eviction. It stores exact terminal frame/pose/uncertainty provenance, stage/error and telemetry, but no colour/depth pixels, dense trajectories or pose graphs; CRC is not encryption or authenticity, and hosts retain the separate retention policy for sensitive imagery. Only the explicit `unverified` quality grade is accepted. `ReconstructionTexturePipelineOptions.enableGlobalSeamOptimization` opts into a bounded global least-squares correction over all sampled manifold atlas seams; cumulative seam/pixel-update telemetry is reported through the existing JNI envelope while the portable result carries the full stage telemetry. The convenience GLB remains `unverified`.

## ARCore-independent runtime

`StandaloneArRuntime` is the guaranteed fallback and directly owns the existing Camera2 + SensorManager + native VIO/mapping session. `StandaloneArSupportProbe` verifies accelerometer, gyroscope, back-camera YUV size, and the configured camera ID before startup. `ArRuntimeSelector` may try an application-supplied `OptionalExternalArRuntimeFactory` (for example a separately packaged ARCore adapter), but falls back on absence, unsupported status, or creation failure without linking this AAR to ARCore. Intrinsics and camera-to-IMU extrinsics remain mandatory device calibration inputs; package presence is never treated as proof of ARCore support. See `docs/FALLBACK.md`.

Host apps own CAMERA runtime permission and lifecycle calls. Typical use:

```kotlin
val vio = ArKernelVio()
val imu = AndroidImuSource(context, vio)

override fun onResume() { super.onResume(); imu.start() }
override fun onPause() { imu.stop(); super.onPause() }
override fun onDestroy() { imu.close(); vio.close(); super.onDestroy() }
```

## Calibrated Camera2 stream

`StandaloneArSupportProbe.inspectCompatibility` builds a privacy-safe versioned capability signature from the exact YUV stream, camera metadata, physical-camera set, IMU properties, ABI, memory class, and hashed build fingerprint. It returns stable reason codes and never grants metric admission from static declarations alone. A host can attach `ActiveDeviceCompatibilityProbe` when creating the standalone runtime; bounded camera image/result and raw IMU timing hooks then measure monotonicity, rates, jitter, gaps, exact timestamp pairing, stream overlap, and observed realtime-versus-uptime behavior. `ActiveCompatibilityTestController` can terminally finish that probe after a fixed bounded window so mapping cannot remain pending accidentally. Mapping remains explicitly paused until the terminal active report passes with trusted camera and camera/IMU calibration. An optional bounded `GuidedRotationObservabilityProbe` compares signed visual rotation with the exact camera-axis IMU prediction supplied to each frame, requiring observable motion and rejecting direction or magnitude disagreement without silently rewriting extrinsics. `GuidedTimeOffsetObservabilityProbe` correlates changing multi-axis visual and body-to-camera gyro angular rates over a bounded ±100 ms grid; weak, ambiguous, boundary, single-axis or constant-motion results are rejected, and accepted results carry conservative peak-width uncertainty/variance. `GuidedTimeOffsetDriftProbe` robustly combines up to 32 accepted windows over at least 60 seconds, reporting ppm drift, uncertainty and residual while rejecting noisy or excessive fits. Neither modifies the live clock mapping. `GuidedMetricConsistencyProbe` separately checks bounded stationary gravity/noise, native visual/inertial translation-direction agreement and scale-gate acceptance. Its runtime result cannot become dimensionally validated without at least three host-supplied physical known-distance observations and their reference uncertainty. For hosts that require all guided checks before mapping, `GuidedMotionAdmissionProbe` owns the active, rotation, time-offset and metric probes as one terminal opt-in gate. `ArKernelSession` feeds it from the exact live observations and remains `DEVICE_COMPATIBILITY_PENDING` until the host finishes the guided sequence; any failed component becomes `DEVICE_COMPATIBILITY_REJECTED`. Runtime admission and physical dimensional validation remain separate report properties. `GuidedMotionTestController` provides a bounded UI-neutral schedule (`HOLD_STILL`, multi-axis rotation, multi-direction translation, optional known-distance measurement) and automatically terminalizes the probe. Guidance callbacks never grant admission: only the measured combined report can do so, and omitting the physical-target stage cannot imply dimensional validation. `CalibrationProfileVerifier` separately verifies bounded canonical P-256/SHA-256 profiles against host-trusted keys, validity, anti-rollback revision, exact capability signature, camera/physical-camera ID, stream, crop and stabilization/distortion modes. `CalibrationTrustPolicy` adds offline key validity windows, revocation, policy rollback protection and per-profile revision floors. `CalibrationTrustPolicyStore` verifies canonical policy bytes with a separate host root key and atomically installs only a strictly newer revision in no-backup app storage; corruption, signature failure, host-floor rollback, and policy expiry fail closed. `CalibrationTargetCaptureProbe` accepts only sharp, sufficiently covered target observations with enough corners and low reprojection error, then requires multiple view and distance bins before producing measurement evidence. Optional OpenCV/AprilTag/custom code plugs into the synchronous `CalibrationTargetPoseAdapter`; `CalibrationTargetPipeline` validates direct-frame extent, exact timestamps/IDs, ordered corner count and bounds, computes core-owned quality/coverage, and never retains image memory. `CalibrationGuidanceController` turns bounded progress into deterministic reacquire/quality/distance/tilt/more/finish states and terminally fails malformed adapter output. The signed payload carries intrinsics, distortion, camera/IMU extrinsics, offset uncertainty and evidence; issuer class cannot be confused with the allowed metric claim. `AdmissionEvidenceStore` can atomically retain the active and guided results in no-backup app storage, but only under an exact capability-signature, calibration-hash, software-revision and expiry match; this advisory cache never bypasses continuous monitors and is not dimensional-validation evidence. `AndroidImuSource` no longer pairs an event with an arbitrarily old value from the other sensor: `ImuSampleSynchronizer` emits strictly increasing common timestamps using bounded interpolation between real samples and never extrapolates. `CameraTimestampNormalizer` withholds initial frames until bounded observations distinguish realtime, uptime, or practically equivalent clocks; one locked median uptime offset then places both Image and CaptureResult timestamps in the IMU realtime domain. Later images continuously check that uptime offset, realtime callback residual, or equivalent-clock relationship has not jumped. A violation terminally stops normalized frames, reports `CAMERA_CLOCK_DISCONTINUITY`, and pauses all mapping until a new session is admitted. In parallel, a subsampled bounded JNI `ArKernelClockAligner` robustly fits affine camera-to-callback time over a minimum ten-second span; `CameraClockDriftPolicy` rejects excessive scale drift in ppm or callback residual RMSE without using that noisy callback fit to rewrite timestamps. `Camera2FrameSource` opens a back camera (or an explicit camera ID), requests the exact calibrated YUV size, consumes only the Y plane, and closes each `Image` after the synchronous native call. The host must pass intrinsics/distortion for that exact camera ID, output size, crop and stabilization mode; the adapter intentionally refuses to guess calibration. When a `CameraCalibrationRuntimeMonitor` is attached, the source explicitly requests the profile-bound crop, video/OIS and distortion modes plus optional fixed focus, then checks every capture result for those values and optional focal/focus/rolling-shutter-skew tolerances. Version-3 signed profiles bind rolling-shutter readout in nanoseconds; version-2 profiles remain decodable but cannot gain that evidence implicitly. A logical multi-camera profile on API 28+ is routed to its advertised physical sensor with `OutputConfiguration.setPhysicalCameraId`, and monitoring uses that sensor's physical capture result. Older APIs, unadvertised physical IDs, or a missing physical result fail closed rather than silently using another lens. Missing or changed required metadata stops frame processing once and immediately pauses the session as `CALIBRATION_CHANGED`; calibration is never replaced mid-map. The requested size must be listed by that camera's `StreamConfigurationMap`.

## Resource tiers

`RuntimeResourcePolicy` derives deterministic performance, balanced, conservative, capture-only or unsupported budgets from the capability signature, completed active timing evidence, bounded frame-processing p95, memory pressure and thermal state. It fixes maximum calibrated pixels, target FPS, IMU queue and reconstruction depth plus dense-depth/semantic enablement. It never changes resolution without a separately calibrated stream profile. `RuntimeResourceController` can refresh or degrade a running tier but cannot upgrade it until a clean restart/re-admission.

Initial decisions are now wired into runtime ownership and bounded session settings. Mapping tiers configure Camera2's best supported FPS range, enforce a timestamp-domain output ceiling, cap the IMU queue and cap pending reconstruction frames. `CAPTURE_ONLY` or unavailable IMU prerequisites select `CameraOnlyArRuntime`: this owner never creates `ArKernelSession`, VIO, a visual tracker, or a SensorManager source. It emits calibrated I420 frames with original normalized timestamps, exposure, ISO, and bounded quality evidence for durable capture/offline reconstruction, while truthfully advertising no 6DoF, planes, anchors, live map, depth, or semantic capability. `CameraOnlyArRuntimeConfig` needs no camera-to-IMU extrinsics. Calibration/timestamp invalidation remains terminal for emitted frames.

`CalibratedStreamProfileSelector` can evaluate at most 64 separately signed profiles, each with the capability signature observed for that exact stream and anchored to the same device/camera identity. It verifies trust, validity/revision, camera/physical-camera identity, dimensions and resource fit before deterministic ranking; it never scales intrinsics. If the current stream alone caused capture-only degradation, the resource decision retains the lower mapping tier that a verified calibrated alternative may re-admit. Thermal, memory and compatibility capture-only decisions cannot use this escape path. A selected profile packages matching runtime config, resource decision and a fresh exact-mode monitor. `ArRuntimeSelector.selectCalibrated` consumes that atomic package and refuses to replace a changed profile unless the caller confirms the old owner is stopped.

`RuntimeExecutionPlanController` guards a running measured plan. Same-plan reason/telemetry refreshes update diagnostics, upgrades are rejected, and every executable budget degradation or calibration-profile hash change becomes a sticky `RESTART_REQUIRED`. The mapping owner immediately exposes `PAUSED/RESOURCE_RESTART_REQUIRED`; the capture-only owner stops frame emission. Neither owner can be started again after invalidation, so a new admitted owner is mandatory. A tier or calibrated-stream change is therefore never a hot swap.

`RuntimeResourceAdmissionCoordinator` atomically combines the immutable startup compatibility reports/profile identity with bounded processing p95, memory pressure and thermal state, then submits every refresh through that guarded owner interface. `AndroidRuntimeResourceMonitor` registers bounded `ComponentCallbacks2` memory notifications and API-29+ thermal callbacks, exposes explicit manual frame-duration sampling, and reports its latest refresh. API 26–28 have no thermal callback and therefore contribute `NORMAL` only as an explicit absence of observed thermal pressure—not as endurance evidence. UI-hidden callbacks are not misclassified as memory pressure.

`TensorRuntimeConformanceSelector` and `MultiOutputTensorRuntimeConformanceSelector` compare fresh CPU and optional delegate runtimes on up to 16 bounded exact-shape golden inputs. Each output head has an exact byte shape, encoding and tolerance. FLOAT32 outputs require finite values and combined absolute/relative tolerance; INT8/UINT8 outputs use an explicit integer tolerance. A delegate exception, output-count/byte-count mismatch, non-finite output or value mismatch in any head closes the complete delegate and returns the still-owned CPU runtime. An invalid CPU reference closes both and aborts selection. These adapter-neutral gates add no LiteRT/ONNX/NNAPI dependency to the core AAR.

`VerifiedInferenceIdentity` can be created only after exact model byte-count and SHA-256 verification. `InferenceBackendIdentityConformanceSelector` then requires CPU and delegate adapters to expose that exact full manifest snapshot, including the exact task set, preprocessing, quantization, labels, metric scale, provenance/licensing, and device-profile metadata. `InferenceBackendSemanticConformanceSelector` combines that identity check with up to 16 bounded decoded golden frames: detections are canonically ordered by semantic and geometric fields rather than backend emission order, then checked for exact class/track/dynamic/surface identity and bounded box/anchor/confidence error. Metric depth is compared over visible pixels with combined absolute/relative meter tolerance and confidence tolerance; `MetricDepthImage` and positioned direct-native `MetricDepthBuffer` interoperate without mutating arrays, buffer positions, padding, or content. Malformed/non-finite CPU output closes both and aborts; any delegate identity, execution, frame, detection, depth-shape, finite-value, or tolerance failure closes it and retains CPU. `VerifiedInferenceBackendAdmission` now constructs separately packaged CPU/delegate factories from independent read-only views of that same verified artifact and returns explicit CPU-only, delegate-construction-failure, conformance-rejection, or delegate-accepted status with deterministic single-owner transfer. `InferenceAdmissionEvidenceStore` atomically caches only accepted reports against a canonical hash of every manifest field plus exact capability, calibration, Golden-suite/tolerance policy, adapter ID/version, canonical typed driver-identity SHA-256, software/policy revision and expiry; rejected, corrupt, stale or mismatched evidence is always a cache miss. `createAndSelectWithEvidence` skips only the full repeated suite for an exact live match: it still rehashes model bytes, reconstructs both backends, requires the delegate itself to report the exact adapter/version/driver execution identity, and runs one decoded CPU/delegate startup sentinel; sentinel failure retains CPU, while any cache miss runs full conformance.

`CapabilityCoveragePlanner` turns up to 256 opaque lab/device-farm candidates into a deterministic weighted set-cover plan of at most 64 devices. It covers observed single and pairwise partitions across API, ABI, RAM, camera presence/hardware/timestamp/frame-rate/logical-camera/metadata and IMU classes, with extra weight for high-risk partitions. Build fingerprints, camera IDs and model names are not coverage dimensions. This optimizes test selection only; it cannot replace Camera ITS, controlled physical rigs or accuracy targets.

`SyntheticCompatibilityFaultSource` feeds the real bounded admission probe with deterministic healthy timing plus single or pairwise timestamp regression, gap, result-dropout, IMU-dropout, latency, ambiguous-clock and disjoint-window faults. It is scalar replay infrastructure—not Camera2 emulation or physical-device evidence—and its bounded catalog is suitable for JVM/CI covering tests. `Camera2LifecycleStateMachine` separately guards asynchronous open/configure/stream/failure/stop ordering with monotonically increasing generations: stale callbacks are closed, terminal disconnect/error/configuration failures are reported once, and `Camera2FrameSource` now tears down the complete pipeline before another start.

`CompatibilitySafetyPolicy` provides canonical bounded disable-only rules over observable API, Camera2 hardware/timestamp, RAM and active-failure classes. P-256 root signatures, validity and monotonic revision floors are checked before a remote policy can replace the permanently valid built-in offline fallback. `CompatibilitySafetyPolicyStore` keeps the optional signed envelope in app-private no-backup storage, atomically installs only a strictly newer valid revision, fails closed on corrupt existing state, and always resolves absent, invalid or expired remote bytes to that built-in fallback. The action type can only disable dense depth, semantics or live mapping, force capture-only, or mark execution unsupported; it cannot grant admission, change calibration or increase a budget. Matching changes pass through the same terminal execution-plan restart guard.

## Coordinated session

`ArKernelSession` queues IMU samples and drains only samples with `timestamp <= Image.timestamp` before each visual frame. It then computes an IMU rotation prediction, runs the visual frontend, and feeds valid general-3D relative poses back into VIO. A calibrated `bodyFromCameraRotation` is mandatory because Android device axes and optical camera axes are generally not aligned; `bodyFromCameraTranslationMeters` carries the metric camera lever arm from the IMU/body origin. Result callbacks run on the camera worker thread.

A frame enters the sparse map at most once and only after `MappingQualityGate` accepts it. Uninitialized or limited VIO, non-tracking frontend state, fewer than 12 accepted tracks, or a new IMU queue overflow pause mapping immediately; three consecutive good frames are required before recovery. `ArKernelSessionResult.mappingGate` exposes `PAUSED`, `RECOVERING` or `ACTIVE` plus the precise reason. `ArKernelSessionResult.spatialMap` reports landmark changes and the bounded dominant plane for compatibility. `ArKernelSession.planes()` exposes all currently extracted surfaces with stable IDs, geometry statistics, observed area and gravity-aware `FLOOR`, `CEILING`, `WALL`, `SLOPED` or `UNKNOWN` semantics. Floor versus ceiling uses the current metric camera side of the plane rather than an arbitrary normal sign. `ArKernelSession.roomLayout()` reports selected floor/ceiling IDs and elevations, a plausibility-gated room height, and sums of observed—not extrapolated—floor, ceiling and wall areas. It does not claim that a partial scan is a closed room boundary. `raycastPlane` tests every active boundary and returns only the nearest valid hit inside observed plane geometry. `createAnchor`, `anchor`, and `removeAnchor` expose stable world-frame anchors. Stopping the Camera2 session resets this transient map and its anchors. `ArKernelSession.saveSpatialMap` exports the native snapshot into `ArKernelMapStore`, which uses Keystore AES-256-GCM, a fresh nonce, authenticated metadata, `AtomicFile`, and no-backup app storage.

Cross-session restore can use `restoreSpatialMapRelocalized` with caller-supplied trusted metric 3D correspondences, or `restoreSpatialMapMatched` after the running scene has accumulated confirmed overlapping landmarks. Repeated descriptors of each confirmed landmark are fused with a bounded bitwise majority vote before persistence and matching. The matched path applies Hamming, ratio and mutual-best gates; native deterministic RANSAC, non-collinearity, inlier-ratio and RMSE gates then decide whether landmarks and complete anchor poses may be transformed and installed. A failed descriptor or geometric gate leaves the active map unchanged. `restoreSpatialMapInCurrentWorld` remains an explicit expert path for an already aligned frame; large-scale place recognition remains outside this foundation. Encryption authenticates bytes but cannot establish spatial alignment. The full calibrated camera-to-body transform is used: mapping composes the rotated metric lever arm into `world_from_camera`, and visual scale correction compares predicted camera-center motion before converting the corrected camera position back to the body origin.

## Depth surfels

`integrateMetricDepthImage` accepts an aligned optical-axis Z-depth `FloatArray` in metres plus an optional confidence plane, performs distortion-aware native unprojection, configurable pixel-stride sampling, radius estimation, and discontinuity-gated local normals without constructing per-pixel Kotlin objects. Sustained pipelines can use `integrateMetricDepthBuffer` with direct native-order `FloatBuffer` inputs: JNI validates current element offsets, remaining capacity, alignment, strides, and optional confidence, then reads synchronously without copying the complete arrays. The host must not mutate or release either buffer until the call returns. `integrateSurfelObservations` accepts an already sampled bounded batch of positive-depth metric camera-space points, confidence, radius, and optional normals together with the exact frame-associated `worldFromCamera`. Stereo, monocular metric-depth, ToF, structured-light, or imported point-cloud adapters can use the same API; LiDAR is not required. The native core transforms samples into world space and confidence-fuses them in 5 cm voxels. Two observations are required before publication through `surfels()`. `raycastSurfel` returns the nearest bounded hit against normal-backed finite discs or approximate half-voxel-capped spheres when no normal is available; a miss is not evidence of observed free space. `renderSurfelDepth` produces a metric camera Z-buffer by distortion-aware per-pixel intersection with confirmed finite discs. `renderSurfelDepthInto` writes the same output synchronously into a reusable writable direct native-order `FloatBuffer` from its current position, avoiding a full JNI result allocation/copy; capacity must cover calibrated width times height and the position is not advanced. Zero remains unknown, normal-less surfels are omitted to avoid false occlusion, and `truncated` reports radius or work-budget clipping. Session writes return `null` unless the mapping gate is active. Relative depth or raw sensor units must be converted and calibrated by the adapter first. Surfels are transient and are not yet a TSDF, mesh, persisted map, or occlusion renderer.

## Temporal metric depth

`TemporalMetricDepthFilter` can conservatively stabilize a camera-aligned `MetricDepthBuffer` before session integration. `TemporalDepthInferenceBackend` can instead own/decorate a metric-depth or combined inference backend so filtering always occurs before the scheduler callback and normal session integration. It reprojects history with the exact previous/current world poses and calibrated distortion, z-buffers the predicted surface, and blends only current valid pixels that pass absolute and relative consistency gates. It never fills current holes. Frame order, gap, calibration, direct-buffer, and 4,194,304-pixel limits are explicit; telemetry reports blended and rejected history pixels.

## On-device inference SPI

`OnDeviceInferenceBackend` is the dependency-free Android boundary for separately packaged LiteRT, ONNX Runtime, MediaPipe, or host engines. Every backend exposes a validated version-2 `ModelManifest` with model/version ID, SHA-256, SPDX license, HTTPS source, tasks, input normalization/quantization (including quantized scale/zero point), labels, metric-depth conversion, byte size, and at most 64 measured device profiles. Profiles use exact capability signatures plus backend ID/version and a typed canonical driver identity over observed API/provider/version/feature-level and a hashed accelerator name; model-name patterns, wildcard reuse and duplicate execution environments are rejected, and lookup never falls back across an OTA/runtime/driver change. `ArKernelTensorPreprocessor` can deterministically resize/normalize a direct camera frame into a reusable direct FLOAT32, INT8, or UINT8 NHWC tensor without adding an ML dependency. `ArKernelDepthPostprocessor` converts a direct one-channel model tensor into camera-sized metric depth plus interpolation-validity confidence, with explicit direct/inverse and unit conversion contracts. `MetricDepthTensorBackend.createVerified` composes both stages around a narrow `SingleInputTensorRuntime`, verifies the exact model bytes, reuses bounded raw tensor buffers, rejects partial runtime output, and leaves LiteRT/ONNX/delegate policy in a separately packaged adapter. `SemanticDetectionTensorBackend.createVerified` adds bounded row-based box decoding, clipping, confidence filtering and deterministic NMS while validating every class against the manifest. `AnchorFreeDetectionTensorBackend` supports bounded YOLOX-style objectness/class rows and RT-DETR-style normalized rows with probability, sigmoid, or softmax scores; `SsdDetectionTensorBackend` supports the four-output SSD/EfficientDet `Detection_PostProcess` contract. `DistributionFocalDetectionTensorBackend` decodes validated merged multi-level DFL rows used by NanoDet-/PicoDet-style exports; `SeparatedDistributionFocalDetectionTensorBackend` accepts an explicitly ordered class/regression tensor pair for every feature level. All remain runtime-neutral and reject malformed shapes, quantization, byte counts, classes, and candidate counts. A genuine multi-head model can use `DepthAndDetectionTensorBackend.createVerified` and `MultiOutputTensorRuntime` to preprocess and execute once, then emit co-timestamped metric depth and semantic boxes from explicitly ordered outputs. Classes configured as dynamic zero depth/confidence inside a padded, pixel-budgeted union of their boxes before temporal filtering or surfel integration. Adapters with one-channel class-index segmentation can use `ArKernelClassMaskPostprocessor` for bounded pixel-level FLOAT32/INT8/UINT8 masking instead of coarse boxes. `BoundedInferenceScheduler` runs one request at a time with no queue and explicit `RATE_LIMITED`, `THERMAL_PAUSED`, `BUSY`, `OUT_OF_ORDER`, and `CLOSED` results. An optional `InferenceCadenceController` uses bounded latency EWMA/p95 telemetry, target duty cycle, failure backoff, and host-supplied thermal state to adapt cadence without creating a queue. `AndroidInferenceThermalMonitor` can feed it from `PowerManager` on API 29+ while safely falling back to `NORMAL` on API 26–28. `PerceptionFrame` keeps direct image memory, calibration, timestamp, and exact world pose together; output cannot replace that pose. `TrackedInferenceBackend` can add bounded deterministic class-aware IoU IDs only to detections lacking model-provided IDs. `ArKernelPerceptionPipeline.create` owns the correctly ordered tracker → temporal-depth → adaptive scheduler → optional Android-thermal chain and offers direct submit-plus-session-integration without adding a queue. `integrateInferenceOutput` routes only declared metric depth and bounded semantic detections through existing session safety gates. No model or ML runtime is silently bundled. See `docs/INFERENCE.md`.

## Semantic 3D observations

`projectSemanticDetection` accepts a calibrated detection pixel plus the exact frame-associated `worldFromCamera` returned in `ArKernelSessionResult`; it unprojects a ray and can require an observed floor or wall boundary. No hit means no object. `integrateSemanticObservation` accepts a model-manifest class ID, optional source track ID, confidence, dynamic flag and an already metric world position. The host must derive that position from trusted depth, triangulation or bounded raycasting; a 2D detection alone is insufficient. The session returns `null` while its geometric mapping gate is paused. `semanticObjects()` exposes only confirmed objects, while `pruneSemanticObjects()` advances static/dynamic expiry even when an inference frame has no detections. Labels remain adapter-owned and class `0` means unknown. Semantic objects are transient and are not yet written to `ARKMAP01`.
